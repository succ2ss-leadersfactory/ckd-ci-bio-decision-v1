# v39 UI/UX Enhancement Design Guide

이 문서는 「종근당/C1바이오 영업팀장 AI 리더십 Lab Journey」 v39 preview의 UI/UX 고도화 기준 문서다.

## 1. 진행 판단

지금은 UI/UX 고도화를 시작하기에 적절한 시점이다.

이유는 다음과 같다.

1. 5~13단계의 기능 흐름이 안정화되었다.
2. 6~13단계의 현장언어화 1차 작업이 완료되었다.
3. v39 Smoke와 전체 smoke가 통과하고 있다.
4. 운영 route `/journey.html`이 아니라 preview route `/journey-v39-preview.html`에서 안전하게 실험할 수 있다.
5. 이제 남은 핵심은 기능 추가가 아니라 교육생의 이해 속도, 입력 편의성, 화면 신뢰감, 접근성 개선이다.

단, 이번 작업은 단순 시각 장식이 아니다.

```txt
예쁘게 꾸미기보다, 판단을 쉽게 만드는 시각 구조화가 목표다.
```

## 2. UI/UX 고도화 목표

| 목표 | 설명 |
|---|---|
| 이해 속도 향상 | 교육생이 3초 안에 현재 단계와 할 일을 알 수 있어야 한다. |
| 입력 피로 감소 | 긴 설명보다 체크리스트, 카드, 요약 배지로 입력 기준을 보여준다. |
| 단계 연결성 강화 | 5~13단계가 지표 → 단서 → 행동 → 역할 → 대화 → AI 초안 → 안전선 → 실행 메모 → 질문으로 이어짐을 보여준다. |
| 현업 신뢰감 강화 | 팀장급 교육생에게 너무 가볍거나 유아적으로 보이지 않게 한다. |
| 접근성 개선 | 색만으로 구분하지 않고, 텍스트와 아이콘을 함께 사용한다. |
| 모바일/태블릿 대응 | 교육장에서 태블릿과 노트북 모두 편하게 사용할 수 있어야 한다. |

## 3. 디자인 원칙 10개

### 원칙 1. 한 화면 한 행동

각 단계에서 가장 중요한 행동은 하나로 보여야 한다.

| 단계 | 한 화면 한 행동 |
|---:|---|
| 5 | 이번 2주 동안 볼 지표를 고른다 |
| 6 | 고객 활동 기록에서 단서를 찾는다 |
| 7 | 단서를 2주 행동 방향으로 바꾼다 |
| 8 | 팀원이 실제로 움직일 수 있게 역할을 다듬는다 |
| 9 | 팀원에게 어떻게 꺼낼지 정한다 |
| 10 | AI에게 2주 실행 초안을 부탁할 질문을 만든다 |
| 11 | 말해도 되는 선을 확인하고 표현을 고친다 |
| 12 | 2주 실행 메모를 완성한다 |
| 13 | 교육장에서 함께 이야기할 질문을 정리한다 |

### 원칙 2. 설명보다 구조가 먼저 보여야 한다

긴 설명문보다 단계 번호, 대표 아이콘, 제목, 진행 상태, 이번 화면에서 할 일을 먼저 보여준다.

### 원칙 3. 그래픽은 장식이 아니라 정보 역할을 해야 한다

아이콘과 인포그래픽은 예쁜 장식이 아니라 의미를 전달해야 한다.

| 의미 | 권장 아이콘/그래픽 |
|---|---|
| 확인 | 돋보기, 체크 표시 |
| 방향 | 화살표, 갈림길, 나침반 |
| 사람/역할 | 사람 아이콘, 역할 카드 |
| 대화 | 말풍선 |
| AI 활용 | Spark, 작은 AI badge |
| 안전선 | 방패, 경고 삼각형, 안전 체크 |
| 최종 메모 | 체크리스트, 문서 카드 |
| 토의 질문 | 질문 카드, 말풍선 묶음 |

### 원칙 4. 기업교육 톤을 유지한다

이모티콘은 과하게 쓰지 않는다. 캐릭터형보다 정돈된 line icon, badge, card를 우선한다.

적절한 톤:

```txt
친절하지만 가볍지 않게
전문적이지만 어렵지 않게
정돈되어 있지만 딱딱하지 않게
```

### 원칙 5. 색은 의미별로 제한한다

색은 많을수록 좋은 것이 아니다. 의미별 색상 체계를 고정한다.

| 색상 역할 | 사용 위치 |
|---|---|
| Emerald | 실행, 완료, 현장 행동 |
| Sky/Cyan | 확인, 기록, 데이터, 질문 |
| Violet/Indigo | 사람, 역할, 대화 |
| Amber | 주의, 최소 기준, 확인 필요 |
| Rose | 위험 표현, 안전선 점검 |
| Slate | 기본 텍스트, 배경, 중립 정보 |

### 원칙 6. CTA는 한 번에 하나만 강조한다

한 화면에서 가장 중요한 버튼만 진하게 보인다. 보조 버튼은 outline 또는 white button으로 처리한다.

### 원칙 7. 최소 입력 기준을 체크리스트로 보여준다

“최소 결과물” 같은 표현보다 “최소로 남길 것” 체크리스트가 좋다.

예:

```txt
□ 먼저 볼 고객군 또는 조건
□ 팀원별 역할과 지원
□ 이번 2주에 할 일
□ 말해도 되는 선
□ 팀원에게 꺼낼 첫 문장
```

### 원칙 8. 이전/현재/다음 흐름을 항상 보여준다

각 단계의 상단 또는 중단에 다음 3개 카드를 둔다.

```txt
앞에서 가져온 것
지금 할 일
다음 화면에서 쓸 것
```

### 원칙 9. 접근성은 디자인 품질이다

- 색만으로 상태를 구분하지 않는다.
- 아이콘에는 텍스트를 반드시 붙인다.
- 버튼 크기는 터치 가능한 크기로 둔다.
- placeholder만으로 설명하지 않는다.
- 긴 문장은 2~3줄 이하로 끊는다.
- 카드 안의 텍스트 대비를 충분히 확보한다.

### 원칙 10. 기능 흐름을 흔들지 않는다

이번 고도화는 화면 이해도와 사용성을 높이는 작업이다. 5~13단계의 데이터 구조와 저장 구조는 건드리지 않는다.

## 4. 공통 UI 패턴

### 4.1 Step Hero Header

각 단계 상단에 공통 hero 영역을 둔다.

구성:

```txt
단계 badge + 대표 icon
한 줄 제목
한 줄 설명
진행 상태 badge 2~4개
```

### 4.2 Flow Strip

5~13단계 흐름을 작은 인포그래픽으로 표시한다.

```txt
지표 → 단서 → 행동 → 역할 → 대화 → AI 초안 → 안전선 → 실행 메모 → 질문
```

현재 단계만 강조하고, 이전 단계는 완료/참고 상태로, 이후 단계는 흐리게 보여준다.

### 4.3 Action Triplet Cards

각 단계마다 같은 구조의 3개 카드를 배치한다.

```txt
앞에서 가져온 것
지금 할 일
다음 화면에서 쓸 것
```

### 4.4 Minimum Checklist Card

“최소로 남길 것”을 체크리스트 카드로 보여준다.

### 4.5 Safety Strip

제약영업 관련 민감 정보와 말해도 되는 선은 모든 AI/최종 메모 관련 화면에 반복해서 짧게 보여준다.

```txt
실제 고객명, 병원명, 의료진명, 제품명, 내부 매출·처방 수치, 개인정보는 입력하지 않습니다.
```

## 5. 단계별 대표 아이콘 체계

이모티콘은 코드상 빠르게 적용할 수 있지만, 최종적으로는 일관된 SVG/line icon으로 전환하는 것이 좋다.

| 단계 | 의미 | 권장 표현 |
|---:|---|---|
| 5 | 지표 선택 | Target / Gauge |
| 6 | 기록에서 단서 찾기 | Search / FileSearch |
| 7 | 2주 행동 방향 | Compass / Route |
| 8 | 팀원 역할 | Users / Network |
| 9 | 대화 시작 | MessageCircle |
| 10 | AI 질문 | Sparkles / Bot |
| 11 | 말해도 되는 선 | ShieldCheck / AlertTriangle |
| 12 | 실행 메모 | ClipboardCheck |
| 13 | 함께 볼 질문 | MessagesSquare / HelpCircle |

## 6. 5~13단계 화면별 개선안

### 5단계. 우리 팀 관리 지표 선정

현재 문제:

- 이후 단계 전체를 여는 기준인데, 시각적으로 “시작점”이라는 느낌이 약할 수 있다.

개선 방향:

- “이번 2주 동안 무엇을 볼 것인가”를 큰 카드로 보여준다.
- 선택한 지표가 6단계로 넘어간다는 연결 화살표를 둔다.
- 지표를 숫자 자체가 아니라 “팀장이 볼 신호”로 설명한다.

추천 그래픽:

```txt
Target icon + 2주 관찰 lens
```

### 6단계. 고객 활동 기록에서 단서 찾기

현재 문제:

- 단서와 고객군을 혼동할 가능성이 있다.

개선 방향:

- “기록에서 본 단서”와 “아직 모르는 것”을 좌우 카드로 분리한다.
- 단서 카드는 돋보기 icon을 사용한다.
- “고객에게 점수를 매기는 화면이 아님”을 작은 safety strip으로 표시한다.

추천 인포그래픽:

```txt
기록 → 단서 → 질문
```

### 7단계. 단서를 2주 행동 방향으로 바꾸기

현재 문제:

- 단서 카드와 고객군/조건 변환 관계가 복잡하다.

개선 방향:

- 변환표를 화살표 카드형으로 유지하되 더 압축한다.
- “고객군”과 “점검 조건”을 색으로 구분한다.
- F 안전선 점검 조건은 고객군이 아니라 모든 활동 앞의 필터로 표시한다.

추천 인포그래픽:

```txt
단서 카드 → 고객군 후보 / 점검 조건 → 2주 행동
```

### 8단계. 팀원 역할 다듬기

현재 문제:

- 역할 배정으로 오해할 수 있다.

개선 방향:

- “누구에게 시킬까”가 아니라 “움직이게 하려면 무엇이 필요할까”를 시각화한다.
- 팀원 카드에 역할, 준비물, 팀장 지원, 확인 질문, 조심할 표현을 badge로 나눈다.

추천 그래픽:

```txt
팀원 → 맡길 일 → 팀장 지원
```

### 9단계. 팀원에게 어떻게 꺼낼지 정하기

현재 문제:

- 대화 화면이 길어질 수 있다.

개선 방향:

- “평소 첫마디”와 “실제로 쓸 첫 문장”을 전후 비교 카드로 둔다.
- 말풍선 그래픽을 활용한다.
- 압박으로 들릴 수 있는 표현과 지원이 보이는 표현을 대비한다.

추천 인포그래픽:

```txt
일단 해보세요 → 왜 하는지 + 어디까지 + 무엇을 도울지
```

### 10단계. AI에게 2주 실행 초안을 부탁할 질문 만들기

현재 문제:

- AI가 답을 정한다는 느낌을 줄 수 있다.

개선 방향:

- AI badge를 “초안 정리 도우미”로 표시한다.
- 입력 정보 묶음과 출력 초안을 분리한다.
- “AI 초안은 완성본이 아닙니다”를 고정 강조한다.

추천 인포그래픽:

```txt
내 메모 묶음 → AI 초안 → 팀장 수정
```

### 11단계. 말해도 되는 선 확인하기

현재 문제:

- 안전선이 법무/규제 교육처럼 무겁게 느껴질 수 있다.

개선 방향:

- 위험 표현을 “빼야 할 말”로 보여준다.
- 안전 표현을 “다시 쓸 말”로 보여준다.
- 방패 icon과 작은 경고 badge를 활용한다.

추천 인포그래픽:

```txt
위험한 말 → 다시 쓴 말 → 최종 메모
```

### 12단계. 2주 실행 메모 완성하기

현재 문제:

- 최종 카드가 보고서처럼 느껴지면 입력 부담이 커진다.

개선 방향:

- “가져갈 메모” 느낌의 카드 디자인을 적용한다.
- 필수 입력 5개를 체크리스트로 보여준다.
- 복사 버튼을 명확히 강조한다.

추천 그래픽:

```txt
한 장 메모 + 체크리스트
```

### 13단계. 함께 이야기할 질문 정리하기

현재 문제:

- 평가표나 강사용 채점표처럼 보이면 안 된다.

개선 방향:

- 질문 카드 묶음으로 보여준다.
- “왜 그렇게 봤는가 / 어디가 막힐 수 있는가 / 함께 물어볼 질문” 3열 구조를 유지한다.
- 2주 후 다시 볼 질문은 회고 카드로 분리한다.

추천 그래픽:

```txt
실행 메모 → 질문 카드 → 2주 후 회고
```

## 7. 구현 우선순위

### 1순위. 6~9단계

가장 복잡한 판단 전환 구간이다.

- 6단계: 단서 카드 시각화
- 7단계: 단서 → 2주 행동 변환 인포그래픽
- 8단계: 팀원 역할 badge 구조
- 9단계: 전후 말풍선 비교

### 2순위. 10~11단계

AI와 안전선의 오해를 줄이는 구간이다.

- 10단계: AI는 초안 도우미라는 구조 표시
- 11단계: 위험한 말 → 다시 쓴 말 구조

### 3순위. 12~13단계

마무리 품질 인상을 높이는 구간이다.

- 12단계: 2주 실행 메모 카드 완성도 향상
- 13단계: 질문 카드와 2주 후 회고 카드 정리

## 8. 개발 구현 방식

### 방식 A. 공통 컴포넌트 도입

아래 공통 컴포넌트를 만드는 방식을 권장한다.

```txt
V39StepHero
V39FlowStrip
V39ActionTriplet
V39MinimumChecklist
V39SafetyStrip
V39InfoBadge
```

장점:

- 단계별 일관성이 생긴다.
- 이후 v40 또는 다른 직무 팀장 버전 확장 시 재사용 가능하다.

주의:

- 한 번에 전 단계에 적용하지 않는다.
- 6~7단계에 먼저 적용해 검증한다.

### 방식 B. 기존 파일 안에서 부분 개선

현재처럼 각 UX 파일 안에서 카드와 문구를 직접 개선한다.

장점:

- 빠르다.
- 리스크가 낮다.

단점:

- 중복 코드가 늘어난다.
- 전체 디자인 일관성 관리가 어렵다.

### 추천

```txt
1차는 방식 A로 공통 컴포넌트 최소 세트를 만든다.
2차는 6~7단계에만 시범 적용한다.
3차 검증 후 8~13단계로 확장한다.
```

## 9. 접근성 체크리스트

| 항목 | 기준 |
|---|---|
| 색상 의존 | 색만으로 상태를 구분하지 않는다. |
| 텍스트 대비 | 작은 글씨도 충분한 대비를 유지한다. |
| 터치 영역 | 주요 버튼은 모바일에서 누르기 쉬워야 한다. |
| 긴 설명문 | 2~3줄 이상이면 카드/체크리스트로 나눈다. |
| 아이콘 | 아이콘만 두지 않고 텍스트를 함께 둔다. |
| 입력칸 | placeholder만으로 의미를 전달하지 않는다. |
| 상태 표시 | “저장됨/미작성/보완 필요”를 텍스트로 보여준다. |
| 모바일 | 1열 스택이 자연스럽게 보여야 한다. |
