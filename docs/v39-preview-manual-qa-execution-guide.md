# v39 Preview Manual QA Execution Guide

## 1. 목적

이 문서는 `journey-v39-preview.html` 수동 QA를 실제 브라우저에서 실행할 때 사용하는 절차서입니다.  
자동 검증은 통과했지만, 고객 시연 전에는 실제 URL 접근, 브라우저 콘솔, 저장·연결 흐름, 반응형 화면을 별도로 확인해야 합니다.

현재 자동 검증 통과 커밋:

```text
5837a78ed48444bc74821a41db11765a1370aa26
```

상태:

```text
자동 검증 완료 / 브라우저 수동 QA 필요
```

## 2. 확인 대상 URL

수동 QA 담당자는 실제 배포된 Vercel preview URL을 입력해 확인합니다.

```text
https://<vercel-preview-domain>/journey-v39-preview.html
```

브랜치 기반 URL을 사용할 경우 예시는 다음과 같습니다.

```text
https://ckd-ci-bio-decision-git-feature-v37-preview-shell-succ2ss-leadersfactorys-projects.vercel.app/journey-v39-preview.html
```

단, Vercel preview 도메인은 배포 설정에 따라 달라질 수 있으므로 실제 접근 가능한 최신 URL을 우선 사용합니다.

## 3. 브라우저 QA 준비

### 3.1 브라우저

우선순위:

```text
1. Chrome PC
2. Chrome 또는 Edge 태블릿 크기
3. 모바일 세로 화면
```

### 3.2 브라우저 초기화

QA 전 브라우저 개발자 도구에서 다음을 권장합니다.

```text
Application → Local Storage → 해당 도메인 → ckd.v39.* key 삭제
Console 탭 열어 오류 확인 준비
Network 탭은 필요 시 새로고침 후 확인
```

### 3.3 기록 문서

결과는 아래 문서에 기록합니다.

```text
docs/v39-preview-manual-qa-run.md
```

## 4. 빠른 접속 확인

| 순서 | 확인 항목 | 기대 결과 |
|---:|---|---|
| 1 | URL 접속 | 화면 정상 로드 |
| 2 | HTML title | `C1바이오 영업팀장 AI 리더십 Lab Journey` |
| 3 | Console | 치명적 오류 없음 |
| 4 | 화면 문구 | preview, v39, DOM 후처리, internal, shell 미노출 |
| 5 | 첫 화면 | 교육용 가상 자료와 민감정보 입력 금지 안내 확인 |

## 5. 최소 End-to-End QA 절차

### 5.1 테스트 입력 규칙

수동 QA에서는 실제 고객명, 병원명, 의료진명, 제품명, 내부 매출·처방 수치, 개인정보를 입력하지 않습니다.

사용 가능한 예시 표현:

```text
고객 유형 A
가상 고객군
교육용 고객군
팀원 역할 A
2주 실행 방향
승인 자료 범위 확인
표현 안전선 점검
```

### 5.2 핵심 흐름 확인

| 흐름 | 실행 | 기대 결과 |
|---|---|---|
| 5→8 | 5단계에서 Dashboard 분석 결과 저장 후 8단계 이동 | 8단계 상단에 5단계 결과 표시 |
| 6→7 | 6단계에서 고객 판단 저장 후 7단계 이동 | 7단계 상단에 고객 판단 결과 표시 |
| 7→8 | 7단계에서 고객 대응 전략 저장 후 8단계 이동 | 8단계 상단에 고객 전략·팀원 배정 방향 표시 |
| 8→9 | 8단계에서 팀원 역할 저장 후 9단계 이동 | 9단계 상단에 담당 고객군·역할 미션 표시 |
| 9→10 | 9단계에서 AI Call Plan 결과 저장 후 10단계 이동 | 10단계 상단에 점검 대상 문장 표시 |
| 10→11 | 10단계에서 컴플라이언스 정리 결과 저장 후 11단계 이동 | 11단계 상단에 안전 문장·체크리스트 표시 |

개발자 도구에서 아래 key 생성 여부를 확인합니다.

```text
ckd.v39.dashboardAnalysis.result.v1
ckd.v39.customerJudgment.result.v1
ckd.v39.customerStrategy.result.v1
ckd.v39.memberRole.result.v1
ckd.v39.aiCallPlan.result.v1
ckd.v39.complianceCleanup.result.v1
ckd.v39.finalCallPlan.result.v1
```

확인 기준:

```text
각 key가 저장 시점에 생성됨
JSON 파싱 오류 없음
단계 이동 후 값 유지
진행 초기화 시 참여자·진행 단계 초기화 확인
```

## 8. 반응형 QA

| 화면 | 확인 기준 |
|---|---|
| PC | 카드, 버튼, textarea가 정상 표시됨 |
| 태블릿 가로 | 2~3열 카드가 읽기 가능한 폭으로 표시됨 |
| 태블릿 세로 | 좌우 잘림 없이 스크롤 가능 |
| 모바일 세로 | 핵심 버튼과 입력창 접근 가능 |

## 9. Go / No-Go 판단 기준

### Go

```text
자동 CI 전체 success
v39 Readiness Audit success
URL 정상 접속
브라우저 콘솔 치명적 오류 없음
고객 시연 화면 내부 문구 미노출
민감정보 입력 유도 없음
5→12단계 저장·연결 흐름 정상
주요 복사·초안·새로고침 버튼 정상
PC/태블릿/모바일 핵심 진행 가능
```

### Conditional Go

```text
기능 핵심 흐름은 정상이나, 일부 문구·간격·반응형 개선이 필요함
시연 전 강사가 우회 가능한 경미 이슈만 존재함
```

### No-Go

```text
URL 접근 실패
치명적 콘솔 오류
5→12단계 연결 중단
민감정보 입력 유도 문구 발견
preview/v39/internal 등 내부 개발 문구 고객 화면 노출
점수화·등급화·평가처럼 보이는 표현 발견
```
