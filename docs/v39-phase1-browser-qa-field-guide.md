# v39 Phase 1 브라우저 확인 현장 안내

## 1. 이 문서는 언제 쓰나

`/journey-v39-preview.html`을 실제 화면으로 열어 보고, 5~13단계가 교육장에서 자연스럽게 이어지는지 확인할 때 사용한다.

기존 `v39-phase1-browser-qa-test-data.md`는 입력값 목록이고, 이 문서는 그 입력값을 어떤 관점으로 확인할지 정리한 운영 안내다.

## 2. 확인할 때의 기본 관점

화면을 볼 때는 개발자 관점이 아니라 교육장 운영자와 팀장 교육생 관점으로 본다.

```text
문장이 딱딱하지 않은가
팀장이 실제 회의실에서 쓸 말처럼 읽히는가
저장한 내용이 다음 화면에서 자연스럽게 이어지는가
평가표나 점수표처럼 보이지 않는가
AI가 판단자가 아니라 보조 도구로 보이는가
```

## 3. 단계별 확인 관점

| 단계 | 화면에서 볼 것 |
|---:|---|
| 5 | 숫자보다 팀원별 움직임과 실행 편차를 보게 만드는가 |
| 6 | 고객 반응을 성급하게 기회로 단정하지 않게 만드는가 |
| 7 | 고객별 판단이 이번 2주 대응안으로 좁혀지는가 |
| 8 | 고객 대응안이 팀원별 역할과 지원 포인트로 이어지는가 |
| 9 | 팀원에게 꺼낼 첫마디가 덜 거칠고 더 분명해지는가 |
| 10 | AI에게 맡기는 것이 아니라 AI에 물어볼 질문을 정리하는 흐름인가 |
| 11 | 현장에서 오해될 수 있는 표현을 한 번 더 손보게 하는가 |
| 12 | 고객, 팀원, 대화, 표현이 2주 실행 카드 한 장으로 묶이는가 |
| 13 | 최종 카드가 평가가 아니라 토의거리로 바뀌는가 |

## 4. 연결 확인 순서

아래 흐름이 화면 상단에서 자연스럽게 보이면 1차 확인은 통과로 본다.

```text
5에서 본 팀 신호가 8로 이어진다
6에서 본 고객 판단이 7로 이어진다
7에서 정한 대응안이 8로 이어진다
8에서 잡은 역할이 9와 10으로 이어진다
9에서 고친 첫마디가 10과 12로 이어진다
10에서 만든 AI 초안이 11로 이어진다
11에서 손본 표현이 12로 이어진다
12에서 만든 최종 카드가 13으로 이어진다
```

## 5. 운영자가 특히 볼 문장

브라우저 확인 중 아래 표현이 화면에서 어색하지 않은지 본다.

```text
숫자만 보지 말고, 팀원별 움직임이 어디서 갈리는지 먼저 짚어봅니다
고객 반응을 바로 기회로 단정하지 말고, 확인할 신호와 조심할 해석을 나눠봅니다
고객별 판단을 이번 2주 안에 움직일 수 있는 대응안으로 좁힙니다
팀원이 방어적으로 듣지 않도록, 첫마디부터 다시 잡아봅니다
그대로 말하면 오해될 수 있는 문장을 걷어내고, 팀장이 책임질 수 있는 말로 고칩니다
이번 2주 동안 실제로 움직일 계획을 한 장으로 정리합니다
마지막으로, 팀장의 판단을 함께 이야기할 질문으로 바꿉니다
```

## 6. 통과 기준

아래가 모두 괜찮으면 시연 후보 동결을 검토한다.

```text
5~13단계 연결이 끊기지 않는다
화면 문구가 교육장 문장처럼 읽힌다
점수화나 평가로 오해되지 않는다
PC, 태블릿, 모바일에서 화면이 무너지지 않는다
복사, 다시 불러오기, 초안 채우기 버튼이 작동한다
브라우저 콘솔에 치명 오류가 없다
```
