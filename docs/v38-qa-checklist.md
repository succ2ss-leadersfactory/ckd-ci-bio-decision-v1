# v38 QA Checklist

## 1. 목적

v38은 v37의 DOM 후처리 방식 문제를 반복하지 않기 위해, 정식 React 컴포넌트 방식으로 복구·확장한 Preview Journey다.

본 체크리스트의 목적은 다음과 같다.

- v34 운영 화면 보호 확인
- v36 고객사 시연 확인용 Preview 보호 확인
- v38 12단계 전체 흐름 확인
- 모바일/태블릿 사용성 확인
- 제약영업 AI 안전선과 컴플라이언스 표현 점검
- 고객사 시연 전 수정 우선순위 도출

---

## 2. 보호 원칙 확인

- [ ] `src/full-flow-journey-v34.tsx`를 수정하지 않았다.
- [ ] `src/journey-active.tsx`를 수정하지 않았다.
- [ ] `src/full-flow-journey-v35.tsx`의 v34 위임 구조를 유지했다.
- [ ] v36 Preview는 고객사 시연 확인용으로 보존했다.
- [ ] v38 개발은 `journey-v38-preview.html` route에서만 진행했다.
- [ ] v38은 DOM 후처리, MutationObserver 기반 보강, 강제 innerHTML 삽입을 사용하지 않는다.
- [ ] 고객사 시연용 화면에 preview, 검증, QA, smoke 관련 문구가 노출되지 않는다.

---

## 3. v38 전체 단계 확인

최신 배포 URL 뒤에 `/journey-v38-preview.html`을 붙여 접속한다.

- [ ] 1. 입장·역할 부여

- [ ] 7. 집중/후순위 고객군 선택
- [ ] 8. 팀원별 역할 방향
- [ ] 9. AI 콜플랜 결과물 요청
- [ ] 10. 컴플라이언스 위험 표현 제거
- [ ] 11. 최종 2주 콜플랜 카드
- [ ] 12. 강사용 토의 질문

## 4. 단계 이동 QA

- [ ] 하단 `다음 단계` 버튼으로 1단계부터 12단계까지 이동된다.
- [ ] 하단 `이전 단계` 버튼으로 역방향 이동된다.
- [ ] 상단 단계 칩을 눌러 원하는 단계로 이동된다.
- [ ] 단계 이동 시 화면 상단으로 스크롤된다.
- [ ] 12단계에서는 `다음 단계` 버튼이 비활성화된다.
- [ ] 1단계에서는 `이전 단계` 버튼이 비활성화된다.
- [ ] 새로고침 후 최근 단계가 유지된다.
- [ ] 브라우저 사이트 데이터 삭제 후 1단계부터 시작된다.

---

## 5. 모바일/태블릿 사용성 QA

테스트 권장 기기:

- Galaxy Z Fold 계열
- Galaxy Tab 계열
- iPad 또는 10인치 이상 태블릿
- Chrome 모바일 브라우저

확인 항목:

- [ ] 상단 단계 칩 가로 스크롤이 자연스럽다.
- [ ] 하단 이전/다음 버튼이 화면 하단에서 가려지지 않는다.
- [ ] 긴 카드가 모바일에서 한 줄로 찌그러지지 않는다.
- [ ] textarea 입력 시 하단 버튼이 키보드에 심하게 가려지지 않는다.
- [ ] 고객군 판단 카드의 13개 Data 보기(details)가 모바일에서 과도하게 길지 않다.
- [ ] 최종 2주 콜플랜 카드가 모바일에서도 읽기 쉽다.
- [ ] 강사용 토의 질문은 접기/펼치기 구조로 화면 부담이 낮다.

---

## 6. 고객군 판단 Lab QA

- [ ] 고객군 후보 1~6이 개별 고객이 아니라 가상 고객군 후보임을 이해할 수 있다.
- [ ] 각 고객군 후보에서 기회성, 반응성, 실행 가능성, 리스크가 한 카드 안에 보인다.
- [ ] 전체 13개 Data 다시 보기가 접기/펼치기로 제공된다.
- [ ] 분류 도우미가 판단을 대신하지 않고 참고 기준으로 보인다.
- [ ] 최종 고객군 분류 선택이 가능하다.
- [ ] 분류 이유를 직접 작성할 수 있다.
- [ ] 분류 완료 수가 정상 반영된다.

---

## 7. 집중/후순위 고객군 선택 QA

- [ ] 집중 고객군 1개를 선택할 수 있다.
- [ ] 후순위 고객군 1개를 선택할 수 있다.
- [ ] 관찰/유지 고객군을 선택할 수 있다.
- [ ] 각 선택 이유를 작성할 수 있다.
- [ ] 이유 문장 힌트가 과도하게 정답처럼 보이지 않는다.
- [ ] 2주 실행 우선순위 요약이 자동 표시된다.

---

## 8. 팀원별 역할 방향 QA

- [ ] 팀원 4명의 프로필이 보인다.
- [ ] 팀원별 담당 고객군을 선택할 수 있다.
- [ ] 팀원별 실행 역할을 선택할 수 있다.
- [ ] 팀장 코칭 포인트를 선택할 수 있다.
- [ ] 컴플라이언스 주의 안내를 작성할 수 있다.
- [ ] 팀원별 역할 배분 요약이 표시된다.

---

## 9. AI 콜플랜 요청 QA

- [ ] 입력 금지 기준이 명확하게 보인다.
- [ ] AI에 요청할 결과물을 여러 개 선택할 수 있다.
- [ ] 선택한 결과물만 프롬프트에 반영된다.
- [ ] 판단 맥락을 체크박스로 선택할 수 있다.
- [ ] 추가 요청을 입력할 수 있다.
- [ ] 복사용 AI 프롬프트가 생성된다.
- [ ] 프롬프트 복사 버튼이 작동한다.
- [ ] 프롬프트에 실제 고객명, 병원명, 의료진명, 제품명 입력 유도 문구가 없다.

---

## 10. 컴플라이언스 위험 표현 제거 QA

- [ ] 위험 표현 유형이 명확하게 제시된다.
- [ ] AI 초안 표현을 보고 위험 유형을 선택할 수 있다.
- [ ] 안전한 대체 문장을 직접 작성할 수 있다.
- [ ] 안전 표현 예시 사용 버튼이 작동한다.
- [ ] 내 콜플랜 문장을 직접 점검할 수 있다.
- [ ] 처방 유도, 비교 우위 단정, 허가 외 표현, 민감정보 포함, 과도한 약속 표현이 구분된다.

---

## 11. 최종 2주 콜플랜 카드 QA

- [ ] 집중 고객군을 작성할 수 있다.
- [ ] 후순위 고객군을 작성할 수 있다.
- [ ] 관찰/유지 고객군을 작성할 수 있다.
- [ ] 팀원별 역할을 작성할 수 있다.
- [ ] 2주 실행 우선순위를 작성할 수 있다.
- [ ] 컴플라이언스 주의점을 작성할 수 있다.
- [ ] 팀원에게 말할 첫 실행 문장을 작성할 수 있다.
- [ ] 예시 템플릿 채우기 버튼이 작동한다.
- [ ] 카드 내용 복사 버튼이 작동한다.
- [ ] 카드가 프롬프트처럼 보이지 않고 현업 실행카드처럼 보인다.

---

## 12. 강사용 토의 질문 QA

- [ ] 질문 묶음이 접기/펼치기 구조로 표시된다.
- [ ] 고객군 판단 디브리핑 질문이 있다.
- [ ] 집중/후순위 선택 토의 질문이 있다.
- [ ] 팀원별 역할 방향 토의 질문이 있다.
- [ ] AI 활용 디브리핑 질문이 있다.
- [ ] 컴플라이언스와 최종 실행카드 토의 질문이 있다.
- [ ] 강사용 질문이 교육생 화면을 과도하게 방해하지 않는다.
