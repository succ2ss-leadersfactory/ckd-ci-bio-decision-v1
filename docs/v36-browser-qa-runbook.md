# v36 Browser QA Runbook

## 목적

이 문서는 `journey-v36-preview.html`이 교육장 파일럿 전에 브라우저에서 정상 작동하는지 확인하기 위한 QA 절차서다.

v36은 v35 운영 상태를 변경하지 않고, 독립 preview route에서 실습 고도화를 검증한다.

## 고정 운영 원칙

- `/journey.html`은 v34 운영 유지
- `/journey-v35-preview.html`은 v35 안정 상태 유지
- `/journey-v36-preview.html`에서만 v36 실습 고도화 검증
- `src/full-flow-journey-v34.tsx` 수정 금지
- `src/journey-active.tsx` 수정 금지
- `src/full-flow-journey-v35.tsx`의 v34 위임 import 유지

## QA 대상 URL

```text
https://ckd-ci-bio-decision-git-994c02-succ2ss-leadersfactorys-projects.vercel.app/journey-v36-preview.html
```

## 사전 준비

### 브라우저 캐시 영향 최소화

처음 검증할 때는 시크릿 창 또는 새 브라우저 프로필을 권장한다.

### 기존 v36 localStorage 초기화가 필요한 경우

브라우저 개발자도구 Console에서 아래를 실행한다.

```js
Object.keys(localStorage)
  .filter((key) => key.startsWith('ckd-v36'))
  .forEach((key) => localStorage.removeItem(key));
location.reload();
```

## 전체 통과 기준

- 빈 화면 없이 로딩된다.
- 13단계 전체가 이전/다음 버튼으로 접근 가능하다.
- 각 단계에서 입력, 선택, 복사, 저장이 정상 작동한다.
- v35/v34 보호 원칙에 영향을 주지 않는다.
- 모바일/태블릿 화면에서 주요 버튼과 입력창이 사용 가능하다.

# 공통 UI/UX QA 체크리스트

확인 항목:

- 상단에 현재 단계와 다음 단계가 명확히 표시된다.
- 진행률 바와 `Step n / 13` 표시가 현재 단계와 일치한다.
- 상단 단계 chip을 클릭하면 해당 단계로 직접 이동한다.
- 긴 화면 하단에서 다음 단계로 이동하면 새 단계의 맨 위부터 표시된다.
- 단계 chip 영역이 가로 스크롤되고, 현재 단계 chip이 자동으로 화면 안에 노출된다.
- 하단 이전/다음 버튼이 sticky로 유지된다.
- 모바일 브라우저 하단 시스템 제스처 영역과 다음 단계 버튼이 겹치지 않는다.
- 단계 chip에 `title`, `aria-label`, `aria-current`가 적용되어 접근성이 유지된다.
- `QA 정보 보기 · v36 Preview Smoke` 접힘 영역이 있고, 기본 화면을 과도하게 방해하지 않는다.

통과 기준:

- 참여자가 긴 실습 화면에서도 현재 위치와 다음 행동을 잃지 않는다.
- 단계 이동 후 중간 위치가 아니라 새 단계 상단에서 시작한다.
- 모바일/태블릿에서 하단 이동 버튼을 안정적으로 누를 수 있다.

# 글꼴/가독성 QA 체크리스트

확인 항목:

- 노트북 Chrome에서 본문 한글이 뭉쳐 보이지 않고 장시간 읽기에 부담이 적다.
- 제목, 섹션명, 카드 본문, 버튼, 입력창, 선택창의 글꼴 체계가 일관된다.
- 숫자, 영문, 한글이 함께 있는 Dashboard 지표와 프롬프트 문장이 어색하지 않다.
- textarea와 input 입력 시 표시 글꼴이 본문과 자연스럽게 이어진다.
- 긴 프롬프트/출력 영역의 `pre`, `code`는 고정폭 글꼴로 구분되어 보인다.
- Windows 노트북에서 `Malgun Gothic` fallback이 자연스럽게 작동한다.
- macOS에서는 `Apple SD Gothic Neo`, Android/Chrome 환경에서는 `Noto Sans KR` fallback이 깨지지 않는다.
- Pretendard CDN이 차단되거나 느린 환경에서도 시스템 한글 글꼴로 읽을 수 있다.

통과 기준:

- 교육생이 노트북 화면에서 2~3시간 실습해도 본문, 버튼, 입력창을 명확히 구분할 수 있다.
- 글꼴 로딩 실패 시에도 화면이 깨지지 않고 시스템 글꼴로 정상 표시된다.
- 글꼴 변경으로 레이아웃 밀림, 버튼 잘림, 입력창 overflow가 발생하지 않는다.

# 13단계 QA 체크리스트

## Step 1. 입장

확인 항목:

- C1바이오 영업팀장 역할 설명이 보인다.
- 이름과 팀명을 입력할 수 있다.
- 역할 수락 체크박스가 작동한다.
- 다음 단계 이동이 가능하다.

통과 기준:

- 입력값이 새로고침 후에도 유지된다.

## Step 2. AI 안전선

확인 항목:

- 입력 금지 정보 확인 체크리스트가 보인다.
- 위험 질문 사례 4개가 보인다.
- 안전한 질문 예시 반영 버튼이 작동한다.
- 나의 AI 사용 원칙과 최종 선언문을 작성할 수 있다.

통과 기준:

- 실제 고객명, 기관명, 제품명, 내부 수치, 개인정보, 효과 단정, 고객 압박 표현을 피하도록 안내한다.

## Step 3. 좋은 질문 만들기

확인 항목:

- 제목이 `좋은 질문 만들기 Lab`으로 보인다.
- 1단계 제목이 `일반 질문 선택`으로 보인다.
- `나쁜 질문`이라는 직접 표현이 화면 주요 제목에 남아 있지 않다.
- 2단계 제목이 `질문 진단`으로 보인다.
- 3단계 제목이 `좋은 질문 조건`으로 보인다.
- 최종 질문 생성과 복사가 가능하다.

통과 기준:

- 일반 질문을 안전하고 구체적인 질문으로 다듬는 흐름이 명확하다.

## Step 4. AI Research 전략 Lab

확인 항목:

- Perplexity + NotebookLM Studio 전략회의 Lab 설명이 보인다.
- Perplexity 프롬프트 복사가 가능하다.
- Perplexity 답변 붙여넣기 영역이 있다.
- NotebookLM 소스 패키지 생성 버튼이 있다.
- 소스 패키지 복사 버튼이 있다.
- NotebookLM Studio 보고서 요청문과 슬라이드 요청문이 있다.
- 최종 산출물이 전략회의 보고서와 발표 슬라이드 구성안으로 연결된다.

통과 기준:

- `소스 후보 자동 추출` 버튼은 없어야 한다.
- 최종 결과물 목적이 NotebookLM Studio 보고서/슬라이드 제작으로 유지된다.

## Step 5. Source Check

확인 항목:

- Step 4 산출물 확인 카드가 보인다.
- NotebookLM 소스 패키지, 보고서 초안, 슬라이드 구성안이 불러와진다.
- 출처 신뢰도 체크가 가능하다.
- 최근성 체크가 가능하다.
- 위험 표현을 복수 선택할 수 있다.
- Source Check 프롬프트 복사가 가능하다.
- 사용 가능한 근거, 추가 확인 근거, 제외 표현, 완화 표현, 최종 반영 기준을 작성할 수 있다.

통과 기준:

- Step 4 산출물이 없을 경우에도 화면이 깨지지 않고 안내 문구가 나온다.

## Step 6. 팀원 Dashboard 분석

확인 항목:

- v34 Dashboard 팀원 6명이 보인다.
- 8개 지표가 선행변수, 과정변수, 결과변수, 확산변수로 구분된다.
- 지표별 간략 설명이 표시된다.
- 현재 상황 점검에서 변수 선택이 가능하다.
- 인과 진단문 생성이 가능하다.
- 4단계 복수 선택 안내가 보인다.
- 5단계 선택 요약 카드가 보인다.
- AI 프롬프트에 3단계·4단계 선택값이 반영된다.

통과 기준:

- Dashboard Lab은 낮은 숫자 찾기가 아니라 `선행변수와 과정변수 때문에 결과변수에 문제가 있다`는 인과 진단 구조로 작동한다.

## Step 7. 고객군 판단

확인 항목:

- 고객군 A~D 반응 데이터가 보인다.
- 2주 집중 고객군을 선택할 수 있다.
- 제외/후순위 고객군을 선택할 수 있다.
- 팀원별 역할 배분을 작성할 수 있다.
- AI 콜플랜 초안 생성과 감별 흐름이 작동한다.
- 최종 2주 콜플랜을 작성할 수 있다.

통과 기준:

- 집중 고객군, 제외 고객군, 팀원별 역할, 콜 전/후속조치/CRM/하지 않을 행동이 저장된다.

## Step 8. 실행행동 Map

확인 항목:

- Step 7 고객군 판단 결과를 불러온다.
- 집중 고객군과 제외/후순위 고객군이 표시된다.
- 팀원별 2주 실행행동을 설계할 수 있다.
- 팀원별 담당 고객군, 역할 초점, 콜 전, 콜 중, 콜 후 24시간, CRM, 팀장 점검, 하지 않을 행동을 수정할 수 있다.
- Step 7 콜플랜 기준으로 다시 불러오기 버튼이 작동한다.
- 실행가능성 점검 프롬프트 복사가 가능하다.

통과 기준:

- Step 7의 전략 판단이 Step 8에서 팀원별 실행행동으로 번역된다.

## Step 9. 본사 요청 현장 번역

확인 항목:

- 본사 요청 Brief를 선택하거나 확인할 수 있다.
- 본사 언어를 팀 실행 언어로 변환하는 입력 흐름이 있다.
- 최종 현장 실행 번역문이 저장된다.

통과 기준:

- 본사 요청이 단순 전달이 아니라 팀원 실행 기준으로 바뀐다.

## Step 10. 이해관계자 메시지

확인 항목:

- 상사, 본사, 팀원, 동료 팀장 등 이해관계자별 메시지를 작성할 수 있다.
- 같은 실행 방향을 대상별 언어로 다르게 번역할 수 있다.

통과 기준:

- 메시지가 대상별로 분리되어 저장된다.

## Step 11. 성과대화 감별

확인 항목:

- 성과대화 프롬프트 생성이 가능하다.
- AI 답변 붙여넣기 영역이 있다.
- 감별 기준에 따라 AI 대화문을 검토할 수 있다.
- 최종 현장형 성과대화 문장을 작성할 수 있다.

통과 기준:

- AI 대화문을 그대로 사용하지 않고 감별·수정하게 되어 있다.

## Step 12. 1on1 코칭

확인 항목:

- 팀원별 개입 전략과 코칭 질문을 설계할 수 있다.
- 팀원 상황과 실행 데이터를 반영한다.
- 최종 1on1 질문 또는 대화 흐름을 저장할 수 있다.

통과 기준:

- 압박형 면담이 아니라 원인 진단과 실행 합의 중심으로 구성된다.

## Step 13. Wrap-up

확인 항목:

- 7일 실행계획을 작성할 수 있다.
- 30일 점검 기준을 작성할 수 있다.
- 팀장 실행 선언을 작성할 수 있다.
- 전체 결과 요약 복사가 가능하다.

통과 기준:

- 교육 종료 후 현업 실행으로 이어질 수 있는 산출물이 남는다.

- 13단계 전체 접근 가능

- 파일럿 전 즉시 수정이 필수는 아님

- 저장/복사 기능 전반 오류

- v34/v35 보호 원칙 훼손 가능성 있음
