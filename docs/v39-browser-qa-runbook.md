# v39 Browser QA Runbook

이 문서는 `/journey-v39-preview.html` 기준으로 5~13단계 연결 흐름을 브라우저에서 직접 확인하기 위한 수동 QA 절차서다.

> 주의: 이 문서는 실제 브라우저 클릭 검증 절차다. 자동 smoke 통과와 별개로, 교육장 파일럿 전에는 최소 1회 이상 실제 브라우저에서 확인한다.

## 1. 확인 URL

Production 또는 Preview 배포 URL 뒤에 아래 route를 붙여 확인한다.

```txt
/journey-v39-preview.html
```

예시:

```txt
https://ckd-ci-bio-decision-v1.vercel.app/journey-v39-preview.html
```

결과 기록 문서:

```txt
docs/v39-browser-qa-result.md
```

관련 기준 문서:

```txt
docs/v39-5-13-flow-qa-checklist.md
docs/v39-browser-qa-console-snippet.md
```

## 2. 사전 확인

브라우저 QA 전 아래 상태를 먼저 확인한다.

```txt
C1Bio MVP CI: success
v35 Smoke: success
v36 Smoke: success
v38 Smoke: success
v39 Smoke: success
v40-lite Smoke: success
```

v39 Smoke 핵심 단계:

```txt
Run v39 static smoke check: success
Run v39 scoped TypeScript check: success
Build Vite app: success
Run integrated v39 smoke check: success
```

## 3. 보호 route 회귀 확인

v39 QA 중에도 운영 route는 보호되어야 한다.

확인 항목:

| 항목 | 기대 결과 |
|---|---|
| `/journey.html` 접속 | 기존 운영 화면 유지 |
| `/journey-v39-preview.html` 접속 | v39 preview 화면 표시 |
| v39 조작 후 `/journey.html` 재접속 | 운영 화면 영향 없음 |
| Console runtime error | 없음 |

보류 기준:

- `/journey.html`이 v39 화면으로 바뀐다.
- `/journey.html` 접속 중 오류가 발생한다.
- v39 조작 후 운영 route 저장값이 손상된다.

## 4. v39 진입 확인

`/journey-v39-preview.html` 접속 후 아래를 확인한다.

| 항목 | 기대 결과 |
|---|---|
| 화면 로딩 | 흰 화면 없이 정상 표시 |
| 5~13단계 이동 | 각 단계 진입 가능 |
| 모바일/태블릿 조작 | 주요 버튼·textarea·select 조작 가능 |
| 저장 상태 | 새로고침 후 localStorage 기반 값 유지 |
| Console runtime error | 없음 |

## 5. 5~13단계 이동 순서

아래 순서대로 각 단계를 이동하며 확인한다.

| 단계 | 화면 제목/핵심 메시지 | 확인할 핵심 산출물 |
|---:|---|---|
| 5 | 우리 팀 관리 지표 선정 | 이번 2주 관리 지표 |
| 6 | 고객의 무엇을 확인할 것인가 | 고객 Data 증거 카드, 최종 고객 Data 확인 List |
| 7 | 고객군별 2주 대응 방향 | 고객군 후보/점검 조건, AI 2주 실행 Map 초안 |
| 8 | 팀원별 실행 보완 Map | 역할 미션, 콜플랜 준비물, 팀장 지원 포인트, 리스크 안전선 |
| 9 | 팀원 온도차와 실행 대화 | 팀원이 받아들일 수 있는 첫 문장 |
| 10 | AI 실행계획 프롬프트 | AI 실행계획 초안, 위험 메모, 점검 초점 |
| 11 | 컴플라이언스 정리 | 안전 문장, 최종 체크리스트, 최종 카드 메모 |
| 12 | 최종 2주 실행 카드 | 집중 고객군, 팀원 역할, 2주 실행 우선순위, 첫 문장 |
| 13 | 강사용 토의 | 판단 근거, 보완 지점, 토의거리 |

## 6. 단계별 입력 최소 세트

수동 QA에서는 모든 내용을 완성하지 않아도 된다. 아래 최소 입력만으로 연결 흐름을 확인한다.

### 5단계

- 핵심 실행 지표 1개 선택
- 함께 볼 현장 신호 1개 선택
- 조심할 해석/안전 지표 1개 선택
- 지표 선택 이유 1문장 입력

기대 결과:

- 6단계에서 5단계 기준을 고객 Data 증거로 전환한다는 안내가 보인다.

### 6단계

- 고객 Data 증거 카드 1개 이상 선택
- `아직 부족한 정보` 1개 입력
- `팀원에게 더 확인할 질문` 1개 입력
- AI 결과 붙여넣기 영역에 샘플 텍스트 입력

샘플 텍스트:

```txt
기회로 볼 수 있는 경우
- 고객 질문이 구체적으로 기록되어 있음
- 자료 요청 목적이 확인되어 있음
- 이전 대화와 연결된 질문이 나옴
- 다음 논의 주제가 언급됨

아직 부족한 정보
- 질문의 실제 배경을 팀원에게 확인해야 함

팀원에게 더 확인할 질문
- 고객이 어떤 맥락에서 질문했는지 확인해 주세요.
```

기대 결과:

- `AI 결과 1차 분리 정리`가 표시된다.
- `기회로 볼 수 있는 경우` 항목에 위 4개 bullet이 분리되어 표시된다.

### 7단계

- 6단계 증거가 고객군이 아니라 판단 재료라는 안내 확인
- 고객군 후보 또는 점검 조건 1개에 2주 대응 방향 입력
- 팀원 연결 후보 1개 선택 또는 입력
- AI 2주 실행 Map 초안 붙여넣기

기대 결과:

- `안전선 점검 조건`이 고객군이 아니라 점검 조건으로 표시된다.
- `AI 결과 1차 분리 정리`가 표시된다.

### 8단계

- 7단계 결과가 역할 보완으로 이어진다는 안내 확인
- 팀원 1명 이상에 대해 아래 중 1개 이상 입력
  - 담당 고객군/조건
  - 역할 미션
  - 콜플랜 준비물
  - 팀장 지원 포인트
  - 리스크 안전선

기대 결과:

- 역할 미션이 비어 있어도 부분 입력이 이후 단계에서 반영될 수 있다는 안내가 보인다.

### 9단계

- 8단계 역할 보완 결과가 대화 재료 카드로 표시되는지 확인
- 평소 첫마디 1개 입력
- 목적에 맞게 바꾼 첫마디 1개 입력
- 팀장이 지원할 것 1개 입력

기대 결과:

- 9단계는 실행 지시가 아니라 실행 대화라는 안내가 보인다.
- 8단계 역할 미션/지원 포인트/리스크 안전선이 대화 재료로 표시된다.

### 10단계

- 5~9단계 결과가 AI 실행계획 프롬프트에 묶이는지 확인
- AI 실행계획 초안 또는 위험 메모 또는 점검 초점 중 하나 이상 입력

기대 결과:

- 8단계에서 역할 미션이 없어도 담당 고객군/준비물/지원 포인트/리스크 안전선이 있으면 10단계에 반영된다.
- 9단계 실행 대화가 프롬프트에 반영된다.

### 11단계

- 10단계에서 AI 실행계획 초안이 없어도 위험 메모나 점검 초점이 있으면 점검 대상으로 표시되는지 확인
- 위험 유형 요약 입력
- 안전하게 수정한 문장 입력
- 최종 체크리스트 입력
- 최종 카드 메모 입력

기대 결과:

- 컴플라이언스 위험과 팀원 실행 대화 리스크가 함께 점검된다.

### 12단계

- 11단계 안전 문장·체크리스트·최종 카드 메모가 최종 카드 기준으로 표시되는지 확인
- 아래 필수 항목 입력
  - 집중 고객군 요약
  - 팀원별 역할 요약
  - 2주 실행 우선순위
  - 컴플라이언스 포인트
  - 팀원에게 말할 첫 문장
  - 강사용 토의 메모

기대 결과:

- 최종 카드가 보고서가 아니라 2주 실행 카드로 보인다.
- 13단계로 넘길 토의 메모가 저장된다.

### 13단계

- 12단계 최종 카드가 판단 근거·보완 지점·토의거리로 표시되는지 확인
- 강사용 토의 연결 요약 복사 버튼 확인
- 현업 적용 2주 후 리뷰 질문 확인

기대 결과:

- 13단계가 평가표가 아니라 강사용 디브리핑 질문 화면으로 보인다.

## 7. Console snippet 실행

5~13단계 최소 입력과 부분 입력 회귀 테스트를 마친 뒤 Console에서 아래 문서의 스니펫을 실행한다.

```txt
docs/v39-browser-qa-console-snippet.md
```

필수 기대 결과:

```txt
routeOk: true
parseErrors: none
forbiddenTermsFound: none
selectedEvidenceCards: 1 이상
customerStrategyItems: 1 이상
memberRoleItems: 1 이상
aiCallPlanItems: 1 이상
complianceCleanupFields: 1 이상
finalCallPlanFields: 1 이상
pass: true
```

주의:

- `missingScreenMarkers`는 현재 한 단계만 표시되는 UI 구조에서는 일부 발생할 수 있다.
- `v34FlowKeysFound`는 이전 운영 경로 사용 이력 때문에 존재할 수 있다. v39 조작 중 새로 생성 또는 변경되었는지를 별도로 본다.

## 8. 부분 입력 회귀 테스트

아래 3개는 반드시 별도로 확인한다.

### Case A. 8단계 역할 미션 없이 부분 입력

조건:

- 8단계에서 역할 미션은 비워 둔다.
- 담당 고객군, 콜플랜 준비물, 팀장 지원 포인트, 리스크 안전선 중 하나만 입력한다.

기대 결과:

- 10단계에서 해당 팀원 역할 맥락이 반영된다.
- 12단계에서 역할 반영 수에 포함된다.

### Case B. 10단계 AI 실행계획 초안 없이 위험 메모만 입력

조건:

- AI 실행계획 초안은 비워 둔다.
- 위험 메모 또는 점검 초점만 입력한다.

기대 결과:

- 11단계에서 점검 대상 문장 수에 포함된다.
- 11단계 점검 프롬프트에 반영된다.

### Case C. 12단계 updatedAt 없이 필드 값만 존재

조건:

- 브라우저 QA 중 일반 UI 저장으로 확인하기 어렵다면, 이 항목은 개발자 콘솔 또는 코드 레벨 QA로 확인한다.
- 최종 카드 필드 중 하나라도 있으면 13단계에서 최종 카드 맥락으로 판단해야 한다.

기대 결과:

- 13단계에서 판단 근거·보완 지점·토의거리 요약이 표시된다.

## 9. 금지 표현 확인

각 단계에서 아래 표현이 참여자 화면에 단독 또는 부적절하게 남아 있지 않은지 확인한다.

- CRM 기록
- CRM Data
- CRM 분석
- CRM상 고객 등급
- CRM 기록 품질
- 고객 등급화
- 고객 순위표
- 처방 가능성 단정
- 전환 가능성 단정
- 집중 공략
- 비교 우위 단정
- 미승인 효능 표현
- 세대 특성 단정

## 10. QA 결과 기록 방법

QA 완료 후 아래 문서에 결과를 기록한다.

```txt
docs/v39-browser-qa-result.md
```

최종 판정은 아래 3개 중 하나로 남긴다.

```txt
통과
조건부 통과
보류
```

보류 기준:

- 5~13단계 중 하나라도 진입 불가
- 저장 후 새로고침 시 핵심 값 유실
- 6→7→8→9→10→11→12→13 연결 중 하나라도 끊김
- 주요 화면에 실제 고객명/병원명/의료진명/제품명/내부 수치 입력 금지 문구가 보이지 않음
- 고객 등급화, 처방 유도, 비교 우위 단정, 세대 단정 표현이 남아 있음
- Console runtime error 발생

## 11. 권장 실행 순서

```txt
1. 최신 커밋 기준 CI 확인

4. 5~13단계 순차 이동
5. 단계별 최소 입력 수행

8. 금지 표현 확인
9. 새로고침 후 저장 유지 확인

11. docs/v39-browser-qa-result.md 업데이트
```
