# v39 Shared UX Pilot QA Guide

이 문서는 v39 UI/UX 고도화 1차 시범 적용 결과를 확인하기 위한 QA 가이드다.

## 1. 적용 범위

이번 시범 적용은 전체 5~13단계 중 6단계와 7단계에만 제한했다.

| 단계 | 적용 파일 | 적용 컴포넌트 |
|---:|---|---|
| 6 | `src/journey-v39-customer-judgment-ux-lab.tsx` | `V39FlowStrip`, `V39StepHero`, `V39ActionTriplet`, `V39MinimumChecklist`, `V39SafetyStrip` |
| 7 | `src/journey-v39-customer-priority-ux-lab.tsx` | `V39FlowStrip`, `V39StepHero`, `V39MiniFlow`, `V39ActionTriplet`, `V39MinimumChecklist`, `V39SafetyStrip` |

공통 컴포넌트 파일:

```txt
src/journey-v39-ux-components.tsx
```

## 2. 이번 시범 적용의 목적

이번 작업은 디자인 장식이 아니다. 교육생이 화면을 더 빠르게 이해하고, 입력 기준을 덜 헷갈리게 만드는 것이 목적이다.

핵심 목적:

```txt
지금 어디에 있는지 보인다.
지금 무엇을 해야 하는지 보인다.
앞 단계와 다음 단계가 어떻게 이어지는지 보인다.
최소로 무엇을 남기면 되는지 보인다.
조심해야 할 점이 지나치게 무겁지 않게 보인다.
```

## 3. 새 공통 UX 컴포넌트

| 컴포넌트 | 역할 | QA 관점 |
|---|---|---|
| `V39StepHero` | 단계 아이콘, 제목, 설명, 상태 배지를 한곳에 표시 | 3초 안에 현재 단계와 할 일이 보이는가 |
| `V39FlowStrip` | 5~13단계 흐름과 현재 위치 표시 | 모바일에서 과밀하지 않은가 |
| `V39ActionTriplet` | 앞에서 가져온 것 / 지금 할 일 / 다음 화면에서 쓸 것 표시 | 단계 연결이 더 선명해졌는가 |
| `V39MinimumChecklist` | 최소 입력 기준을 체크리스트로 표시 | 입력 부담을 줄이는가 |
| `V39SafetyStrip` | 조심할 점을 별도 영역으로 표시 | 너무 위협적으로 보이지 않는가 |
| `V39MiniFlow` | 짧은 인포그래픽 흐름 표시 | 복잡한 전환을 쉽게 보여주는가 |

## 4. 6단계 QA 기준

대상 화면:

```txt
/journey-v39-preview.html
6단계 · 고객 기록에서 단서를 찾습니다
```

확인 질문:

| 항목 | 확인 질문 | 결과 | 메모 |
|---|---|---|---|
| 현재 위치 | Flow Strip에서 6단계가 현재 단계로 명확히 보이는가? | 미확인 |  |
| 화면 목적 | 제목만 봐도 고객 기록에서 단서를 찾는 화면임을 알 수 있는가? | 미확인 |  |
| 상태 배지 | 지금 남긴 것, 고른 단서 카드, 메모 상태가 쉽게 읽히는가? | 미확인 |  |
| 단계 연결 | 앞에서 가져온 것 / 지금 할 일 / 다음 화면에서 쓸 것이 자연스러운가? | 미확인 |  |
| 최소 기준 | 단서 카드 1개, 부족한 정보 1개, 질문 1개 기준이 부담을 줄이는가? | 미확인 |  |
| 안전 문구 | 고객을 점수화하지 않는다는 안내가 명확하지만 과하지 않은가? | 미확인 |  |
| 모바일 | 모바일/태블릿에서 카드가 지나치게 길거나 빽빽하지 않은가? | 미확인 |  |

대상 화면:

```txt
/journey-v39-preview.html
7단계 · 이번 2주 동안 어디에 먼저 움직일지 정합니다
```

확인 질문:

| 항목 | 확인 질문 | 결과 | 메모 |
|---|---|---|---|
| 현재 위치 | Flow Strip에서 7단계가 현재 단계로 명확히 보이는가? | 미확인 |  |
| 화면 목적 | 제목만 봐도 단서를 2주 행동으로 바꾸는 화면임을 알 수 있는가? | 미확인 |  |
| MiniFlow | 기록에서 단서 보기 → 2주 행동으로 묶기 → 팀원 역할로 넘기기 흐름이 잘 보이는가? | 미확인 |  |
| 변환표 | 단서와 고객군/점검 조건의 관계가 더 쉬워졌는가? | 미확인 |  |
| 상태 배지 | 단서, 확인 메모, 2주 행동 메모, 함께 볼 팀원 수가 이해되는가? | 미확인 |  |
| 최소 기준 | 7개 체크 항목이 너무 많아 보이지 않는가? | 미확인 |  |
| 안전 문구 | 고객 순위화 금지, AI 초안 확정 금지 안내가 적절한가? | 미확인 |  |
| 모바일 | 태블릿 세로 화면에서 Flow Strip과 MiniFlow가 답답하지 않은가? | 미확인 |  |

## 6. 전문가 관점 점검 포인트

### UX 관점

- 현재 단계, 현재 행동, 다음 단계 연결이 3초 안에 파악되는가?
- 카드가 많아졌지만 오히려 복잡해지지는 않았는가?
- 색과 아이콘이 의미를 돕는가, 장식처럼 보이는가?
- CTA와 입력 영역이 묻히지 않는가?

### 교육공학 관점

- 6단계에서 “단서”와 “고객군”을 혼동하지 않게 도와주는가?
- 7단계에서 “단서 → 행동 → 역할” 전환이 학습 흐름으로 보이는가?
- 최소 입력 기준이 실습 포기를 줄이는가?
- 안전 문구가 학습 흐름을 끊지 않는가?

### 기업교육 운영 관점

- 팀장급 교육생에게 너무 가볍거나 유아적으로 보이지 않는가?
- 이모티콘이 과하게 보이지 않는가?
- 강사가 설명하지 않아도 화면만 보고 다음 행동을 이해할 수 있는가?
- 10~15분 단위 실습 시간 안에 입력을 유도할 수 있는가?

### 접근성 관점

- 색만으로 정보를 구분하지 않는가?
- 작은 텍스트가 너무 많지 않은가?
- 모바일 터치 영역이 충분한가?
- 주요 설명이 placeholder에만 의존하지 않는가?

## 7. 브라우저 확인 절차

1. `/journey-v39-preview.html` 접속
2. 6단계로 이동
3. 화면 상단부터 입력 영역까지 세로로 훑어보기
4. 6단계 QA 표 작성
5. 7단계로 이동
6. MiniFlow, 변환표, ActionTriplet, Checklist, SafetyStrip 확인
7. 7단계 QA 표 작성
8. 모바일/태블릿 폭에서 다시 확인
9. 수정 필요 표현이나 과밀한 카드 위치를 메모

## 8. 통과 기준

아래 조건을 만족하면 8~13단계 확장 적용으로 넘어갈 수 있다.

```txt
1. Flow Strip이 현재 위치를 이해하는 데 도움이 된다.
2. Step Hero가 기존 상단 설명보다 더 빠르게 이해된다.
3. Action Triplet이 단계 연결을 더 분명하게 만든다.
4. Minimum Checklist가 입력 부담을 줄인다.
5. Safety Strip이 과도한 경고처럼 보이지 않는다.
6. 모바일/태블릿에서 스크롤이 자연스럽다.
7. 팀장급 교육생에게 지나치게 가볍거나 장난스럽게 보이지 않는다.
```

## 9. 보류 기준

아래 중 하나라도 있으면 8~13단계 확장을 보류한다.

```txt
1. Flow Strip이 모바일에서 너무 길고 답답하다.
2. 아이콘/이모지가 팀장급 교육생에게 가볍게 보인다.
3. 카드가 늘어나 입력 영역이 지나치게 아래로 밀린다.
4. Safety Strip이 경고처럼 강하게 보여 학습 흐름을 끊는다.
5. 기존보다 화면을 읽는 시간이 길어진다.
6. 강사 설명 없이는 여전히 단계 의미가 이해되지 않는다.
```
